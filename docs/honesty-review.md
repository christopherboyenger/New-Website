# Honesty, money and policy review

Scope: fabricated or placeholder data, zeros shown for unavailable data, reference-product branding, commercial terms outside `src/config/commercial-policy.ts`, forecasts, edits that activate/publish/charge/send, float money, ledger effect keys, disclosure consistency, and the accuracy of `src/server/readiness.ts` / `docs/readiness.md`. Each finding was reproduced with a failing test or traced from a real caller before being fixed.

## Verified clean

- **Reference branding/data:** `grep -ri "noise|getnoise|testingcreators|annie|diaz|20192|24964"` outside `docs/spec` finds only decision records that cite the spec, plus the word "noise" in a particle-animation comment.
- **Fabricated data:** no hard-coded metrics, names, testimonials, logos or faces. Marketing diagrams are non-numeric and labelled as illustrations. Dev fixtures are test-only.
- **Unavailable vs zero:** Home, Organic metric cards and the chart use `awaiting_metrics`/`unavailable` (DEC-013). Rolling counters, the ad impressions card, creator earnings (confirmed $0 with an explanation, payouts "not configured") and installs (omitted when no source reported) are all honest.
- **Commercial terms:** prices, thresholds, plan names, matching credit ($500, `enabled: false`) and the validation charge ($5, `enabled: false`) are read only from `commercial-policy.ts`. The matching banner, billing figure and pricing line render only when enabled. `paymentSetupDisclosure()` is the single disclosure in onboarding (budget and payment steps), pricing, billing (empty state and card-action dialog).
- **Forecasts:** `src/server/forecast.ts` always returns `unavailable`. The UI shows "Reach estimate unavailable" and no numbers.
- **Edits never activate/publish/charge/send:** campaign creation and onboarding completion create Inactive campaigns and draft playbooks. Playbook saves never change status. Budget edits never change status. Publish, activate, pause and toggle are explicit confirmed dialogs. Ad launch drafts never call a provider. Card setup uses Checkout setup mode, which does not charge. Upgrade uses hosted checkout after confirmation.
- **Email "sent" claims:** invitations and verification show the real `sendEmail` status. The password-reset confirmation says "we've sent" whenever a provider is configured, regardless of the per-address result. This is deliberate anti-enumeration, worded "If an account exists…".
- **Money:** amounts are integer cents in storage, commands and ledger. Floats appear only at display or API boundaries (`centsToUsd`, CPM), and parsed input is rounded or parsed digit-wise into cents.
- **Ledger:** the single writer `appendLedgerEntry` requires a non-blank `effectKey`. `ledger_effect_key_unique` plus `onConflictDoNothing` and a values comparison make duplicates no-ops and conflicting duplicates errors. The invoice key is `stripe:<env>:invoice:<id>:paid`. Earnings keys come from `earningEffectKey(post, window)`.

## Reported, not fixed

- **Marketing describes capabilities this build cannot perform yet.** The homepage "Posts to ads" and "AI agent" sections (`src/components/marketing/content.ts`), the integrations badges ("Launch approved posts as … ads"), the creators page ("paid out once they become eligible") and the pricing comparison row "Posts to Meta and TikTok ads" describe ad launching, an MCP endpoint and creator payouts. `docs/readiness.md` lists all three as not implemented. The in-product screens are honest (not-configured notices), and this is product positioning copy owned by marketing. Recommendation: before launch, either gate these lines on the matching capabilities or mark them "coming soon".
- **Reporting API returns `0` totals when nothing has been ingested.** `/api/v1/reports/daily` follows the documented response shape, which has no "unavailable" state. Changing it would break the contract. This is now documented in `docs/api.md` (finding 4).
- **Breakdown dialog empty state** says "No views or spend in this range" even while the workspace is `awaiting_metrics`. It shows no zeros, so it is left as is.
