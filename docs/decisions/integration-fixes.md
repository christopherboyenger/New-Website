# Integration fixes — decisions

- INTEGRATION-FIXES-01 — `created=<campaignId>` on the Organic Campaigns tab shows a success note naming the campaign. While it is still `inactive`, the note says it stays Inactive until activated and that nothing is spent. The row is highlighted only when it's on the current page. The ID is looked up tenant-qualified (an unknown or other-workspace ID is ignored silently), and the parameter is not part of the canonical URL state, so it disappears after the next navigation. — The note confirms the create, and an unknown ID must not reveal anything. — CLAUDE.md non-negotiables 3 and 5; production-ui-plan.md (campaign create → Organic).
- INTEGRATION-FIXES-02 — Sign-up links the visitor's `/start` lead (found only through their own httpOnly lead cookie) to the new account when the lead's email matches the account email (case-insensitive) and the lead isn't linked already. A linking failure never blocks sign-up. — Attribution without letting a shared or stale cookie attach someone else's lead. — production-requirements.md (acquisition attribution); CLAUDE.md non-negotiable 3.
- INTEGRATION-FIXES-03 — The raw install estimate series is keyed `estimate` inside the reporting core (the same name as the stored source), so the Reporting API publishes `installs_by_source` unchanged. The blending rules are unchanged (DEC-012). — One name end to end, and no reference-product naming. — CLAUDE.md non-negotiable 1; docs/api.md.
- INTEGRATION-FIXES-04 — A Meta or TikTok installation is launch-ready only in status `connected` with every launch scope granted (`ads_management` for Meta; TikTok permissions are set on the app, so no scope string is checked). A connected Meta installation without `ads_management` is shown as "can read reports but can't create ads", and saving a draft explains how to reconnect. — Reporting-only grants must not look launch-capable. — production-integration-contracts.md §6; docs/decisions/integrations.md (separate capability scopes).
- INTEGRATION-FIXES-05 — Playbook editor IDs for external reference and image links use the `ref_` prefix, and new ad-rights grants use random `rgt_` IDs (`newId("rgt")`) instead of IDs derived from the post ID. — `med_` is reserved for stored media assets, which don't exist yet (no media storage). — src/lib/ids.ts.
- INTEGRATION-FIXES-06 — An unknown or other-workspace playbook ID on `/home/{org}/playbooks/{id}/edit` now returns HTTP 404: a segment layout above the editor's `loading.tsx` resolves the playbook (tenant-qualified) before streaming starts, and the skeleton is kept. — Honest status codes without losing the loading state. — CLAUDE.md non-negotiable 3 (non-member and nonexistent look identical).
- INTEGRATION-FIXES-07 — Onboarding's payment step reconciles with Stripe on return or "Check again" (`reconcilePaymentSetup`). If the provider can't be reached, it logs a sanitized summary and falls back to the stored provider-confirmed state, never to the browser redirect. — The same effect as a webhook, without trusting the redirect. — production-integration-contracts.md (payments).
