# Workspace shell, Home, Live, global search and messages — decisions

Format: `WORKSPACE-NN — decision — rationale — spec reference`. Everything here is **proposed** behavior for this product; none of it is claimed as recovered reference behavior.

- **WORKSPACE-01** — The sidebar collapses to a 56px icon rail (brand initial, search, icons with tooltips and screen-reader labels). The choice is stored per user in `user_flags.sidebar_collapsed` (not per workspace) through a Server Action; activating Resources in the rail expands the sidebar so the list can open. — The reference shows a collapse control but its collapsed layout was not inspected. — reference-build-specification.md "Workspace shell"; L01.
- **WORKSPACE-02** — Resources lists only working destinations for this product: "Documentation" (`NEXT_PUBLIC_DOCS_URL`) and "Contact support" (`NEXT_PUBLIC_SUPPORT_EMAIL`) when configured; otherwise the note "Documentation isn't published yet." No classic-dashboard, newsletter, webinar, podcast or social links. — The reference links point at the reference product's own properties; the production plan forbids a nonfunctional classic-dashboard link. — production-ui-plan.md "Resources"; L25.
- **WORKSPACE-03** — Brand switcher lists every workspace the user belongs to (alphabetical) and links to `/home/<slug>`; "Create workspace" goes to `/onboarding?new=1`. The layout records the opened workspace with `rememberLastOrg` only when it changed, so `/home` reopens it. — Switching/creation targets were not observed. — L01 "Switch brand".
- **WORKSPACE-04** — Below 768px the sidebar moves into a modal drawer (native `<dialog>`, focus contained, Escape and backdrop close, focus returns to the menu button) opened from a top bar with the workspace name, a labelled "Open navigation" button and a search button. A drawer left open while the window widens past 768px closes. — Mobile layouts were not inspected. — production-ui-plan.md "Proposed mobile and accessibility behavior".
- **WORKSPACE-05** — An unverified email shows a non-dismissible banner at the top of the main panel linking to `/auth/verify`. — Verification state must be visible; the banner does not block work. — production-ui-plan.md auth routes.
- **WORKSPACE-06** — ⌘K / Ctrl+K toggles search from anywhere in the workspace shell (including while typing in a field) and closes the mobile drawer first. The trigger shows ⌘K on Apple platforms and Ctrl K elsewhere (server renders ⌘K; the client corrects after hydration). — Windows behavior was not tested in the reference. — L24; production-ui-plan.md "Offer Ctrl+K and Cmd+K".
- **WORKSPACE-07** — Search scope: campaigns (name or primary hashtag, `#` optional), playbooks (name), approved posts (handle with or without `@`, or caption), creators associated with the workspace (on its roster, in or requesting one of its campaigns, or with a post in it) by display name or social handle, and static pages filtered by the caller's permissions (Members never see Billing, New campaign or Create ads). Five results per group, prefix matches first then alphabetical; LIKE wildcards are matched literally; queries are capped at 100 characters; 200ms debounce; an empty query lists the permitted pages. — Ranking and result layout were not recovered. — L24; production-ui-plan.md "Search overlay".
- **WORKSPACE-08** — Search result destinations: campaign → `campaigns?tab=playbooks&campaign=<id>`; playbook → `/playbooks/<id>/edit`; post → `campaigns?tab=posts&search=<handle>`; creator → `creators?search=<name>`; pages → their route. The `search` query parameter on Organic posts and Creators is a cross-area contract requested from those areas. — No entity detail routes were observed. — L02–L04, L10.
- **WORKSPACE-09** — The Team channel is one persisted conversation per workspace with the deterministic id `cnv_team_<orgId>`, created lazily (idempotently) the first time a member opens it. Only members (`messages:use`) can open, read, post or mark read; every query is qualified by the authorized `orgId`, and a conversation id from another workspace is "not found". — Team identity was not recovered; a deterministic id avoids duplicate conversations under concurrent first opens. — production-ui-plan.md "Messages overlay", "Messaging/invitations".
- **WORKSPACE-10** — Message bodies are plain text: trimmed, CRLF normalized to LF, 1–2,000 characters, rendered as text (markup and links are shown literally), limited to 30 sends per user per minute. Sending marks the author's own read position. — Rich text, attachments, stickers and editing were not specified. — Evidence audit item 1.
- **WORKSPACE-11** — Delivery without a push transport: the conversation loads on open, refreshes every 15 seconds while it is on screen and the tab is visible (and when the tab becomes visible again); the unread badge refreshes every 60 seconds otherwise. "Load earlier messages" pages 50 at a time. — The reference's refresh transport was not recovered; polling is modest and stops in background tabs. — L01/L09.
- **WORKSPACE-12** — Unread = Team messages from other people after the user's read position, or after the user joined the workspace when they have never opened the channel (history from before joining is not unread). The read position only moves forward and never past "now". — Needed for an honest badge for new teammates. — `conversation_reads` contract.
- **WORKSPACE-13** — Support and AI-agent channels are listed as "Not available on this deployment" (Support links to email when a support address is configured); no messages are fabricated. "Message your creators" shows "Requires Unlimited" plus a "See plans" link (owners only) on plans without `creator_messaging`; on Unlimited it states that creator messaging isn't available on this deployment yet, because no creator messaging backend exists. — Support/AI need provisioned services. — production-ui-plan.md "Messages overlay"; DEC-006.
- **WORKSPACE-14** — Dock presentation (minimized / floating window / docked side panel) is stored per user in `user_flags.messages_dock_state` and kept across routes and workspaces. Only the active presentation is rendered. Opening moves focus to the panel heading; minimizing returns it to the launcher; Escape minimizes the floating window. On phones the dock is always a full-width modal panel (page behind is inert, Escape closes) and the phone visit does not change the stored desktop presentation. — Evidence audit item 1 requires mutually exclusive states and focus restoration. — production-ui-plan.md "Messaging opens a full-width panel on phones".
- **WORKSPACE-15** — Home "Organic views" totals approved-post daily metrics for the selected UTC range. When the workspace has approved posts but no daily metric has ever been recorded, the card shows "—" with "No metrics source has reported views for your posts yet." (extending DEC-013); otherwise a period without views shows a confirmed 0 with "No views in this period yet." and no trend line. A trend line is drawn only when the period has views, with a text summary (total, peak day). — Never show a fabricated zero or synthetic trend. — production-ui-plan.md "Successful empty report", "Metrics unavailable".
- **WORKSPACE-16** — Home "Ad impressions" never shows a number: no Meta/TikTok Ads installation → "Connect a Meta or TikTok ad account to run your posts as ads." + Go to Integrations; an installation needing reauthorization/in error → "needs attention" + Go to Integrations; a connected installation → "Ad reporting isn't available yet" because no ad reporting import exists. — Honest states. — L01; production-ui-plan.md Home row.
- **WORKSPACE-17** — "Active Campaigns" lists active campaigns whose approved posts earned (spend > 0) within the selected range, highest spend first, top five, with the range's views and spend; empty state "Nothing to see here yet / No active campaigns with earnings in this period." plus "Create a campaign" for owners (or a note for members) when the workspace has no campaigns. — The reference's sort and limit were not observable (empty account). — L01.
- **WORKSPACE-18** — "<n> posts" counts approved, campaign-attributed posts created in the range (Organic "created" mode) and lists the five newest with platform, posted date (UTC) and lifetime views ("—" when not reported). Empty states distinguish a workspace with no posts ("No posts yet") from a range without posts ("No posts in this period"). "View all posts" carries `from`/`to` so the destination matches the count (the reference link did not carry dates). Post links open only `http(s)` URLs. — Keep counts consistent with the destination. — L01; production-ui-plan.md "links preserve dates".
- **WORKSPACE-19** — Live shows the two rolling counters with "Updated through <UTC time> · <age>" from the latest metric observation and flags them as possibly behind when the latest observation is more than 60 minutes old. The page re-renders its server data every 60 seconds while visible. The globe is a static neutral graticule with no location marks: no permitted city-level location source exists, so the page says creator locations appear once location data is available. — Map, geolocation and transport were not recovered; never simulate activity. — L09; production-ui-plan.md Live row.
- **WORKSPACE-20** — `(workspace)/loading.tsx` is a generic page skeleton because it is the navigation fallback for every workspace route without its own loading state; Home streams its counters and metrics behind section-shaped skeletons, and a new date range re-shows the metrics skeleton rather than the previous range's numbers. `(workspace)/error.tsx` replaces only the main panel (sidebar and dock stay usable) and shows the error digest. — Stable-size loading, no temporary zeros. — production-ui-plan.md "Metrics loading".
