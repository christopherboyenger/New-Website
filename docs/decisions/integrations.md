# Integrations area decisions

Format: `ID — decision — rationale — spec reference`. These are product/implementation decisions where the spec is silent or conflicting; none of them describes observed reference behavior.

- INTEGRATIONS-01 — The public Reporting API uses `Authorization: Bearer <token>` at `{APP_URL}/api/v1`; no org header is accepted, because the organization always comes from the token. — Grants are bound to one org; the reference's `x-noise-org`/`x-noise-token` headers belong to another product. — production-integration-contracts.md §7.
- INTEGRATIONS-02 — Tokens look like `rk_<8 public chars>_<43 secret chars>`. Only the HMAC digest (`tokenDigest(token,"api_grant")`) and the public prefix are stored. The plaintext is shown once, and there is no reveal or rotate endpoint (rotation means create a new token, then revoke the old one). — Spec: "display it once, store a keyed digest plus public lookup prefix; no recurring Show plaintext endpoint". — §7.
- INTEGRATIONS-03 — Many labelled tokens per org (up to 20 active), each with scopes and an expiry of 30/90/365 days or never. This replaces the reference's single shared key per org. — The production contract asks for labelled, scoped, expiring grants. — §7; reference-build-specification §4.
- INTEGRATIONS-04 — Tokens are delegated by the owner who created them. A token stops authenticating as soon as that user no longer holds `api_tokens:manage` in the org (removed, demoted or disabled). — "A removed member's delegated grant stops immediately." — §7.
- INTEGRATIONS-05 — Issuable scopes are `reports:read`, `campaigns:read` and `playbooks:read`. `creators:read` exists in the schema but is not offered until a creators endpoint exists. — We don't grant scopes that do nothing. — §7.
- INTEGRATIONS-06 — Rate limit is 120 requests per 60-second fixed window per token (DB-backed). Headers: `X-RateLimit-Limit/Remaining/Reset` (Reset is Unix seconds). A 429 adds `Retry-After`. The limit is checked before the scope check, so failed calls also count. — The reference's numbers were not recovered. — reference-build-specification §1.
- INTEGRATIONS-07 — API validation is strict. `page_size` > 100 is a 400 (not clamped). Repeated parameters, unknown parameters and malformed IDs are 400s. The ID filter allows at most 100 IDs. Default `order` is `desc` (DEC-011). — Silent clamping or ignoring typos hides client bugs. — reference-build-specification §1.
- INTEGRATIONS-08 — The raw install estimate series is published as `installs_by_source.estimate`. The route maps the reporting core's internal key `noise` to `estimate`. — Never expose the reference product's name. — CLAUDE.md non-negotiable 1.
- INTEGRATIONS-09 — `/api/v1/posts` omits the internal `review_status` field (only approved posts are returned anyway). — Not part of the documented contract. — reference-build-specification §1.
- INTEGRATIONS-10 — Sensitive integration and token changes require: the permission (`integrations:manage` / `api_tokens:manage`), a verified email, and a password confirmation within the last 30 minutes on the same session. The UI asks for the password first and retries once on `requires_recent_auth`. — The step-up window length is unspecified. — §4 step 1; production-requirements.
- INTEGRATIONS-11 — Meta: capabilities are requested separately. "Connect for reporting" asks for `ads_read`. "Connect with ad launch" asks for `ads_read,ads_management`. The Graph API version is pinned to `v24.0`. PKCE is not sent, because its support for this server-side flow has not been confirmed. The business-portfolio (Facebook Login for Business `config_id`) option is not offered, because no configuration ID is provisioned. — Contract: request permissions per capability and add no unsupported PKCE. — §4, §5; production-ui-plan "Meta Ads".
- INTEGRATIONS-12 — TikTok Business: authorize at `business-api.tiktok.com/portal/auth` with `app_id`, `state` and `redirect_uri`. No scopes are sent (they are set on the app) and there is no PKCE. API version `v1.3` is pinned. The token is treated as having no expiry unless the provider returns one. — The Business portal flow documents neither scopes in the URL nor PKCE. — §4.
- INTEGRATIONS-13 — The OAuth start is a same-origin form POST (Origin / Sec-Fetch-Site checked, on top of SameSite=Lax cookies). State is 32 random bytes and only its digest is stored, bound to user, session, org and provider, with a 10-minute expiry. The return path is allowlisted to `/home/<slug>/integrations`. The callback claims the attempt atomically before any check, so a replayed or invalid callback cannot be retried. — §4 steps 2–4.
- INTEGRATIONS-14 — An OAuth connection is `connected` only after a successful read of the granted permissions and assets. No eligible assets, or requested scopes missing from the grant, gives `limited_permissions`. Assets are all accounts the token can read; a per-account picker is a follow-up. — "connected only after verification"; asset selection UI was not specified. — §2, §3.
- INTEGRATIONS-15 — Disconnect disables locally first (status `disconnected`, generation bumped, credentials destroyed and ciphertext wiped), then asks the provider to revoke using the in-memory token. If that remote call fails, the status is `revocation_pending`, and the customer is told to remove the app in the provider's settings and then "Mark as removed". No automatic retry is possible because the token is already destroyed. — Destroying credentials immediately was preferred over keeping a token only for retries. — §4 "Custody, refresh and disconnect".
- INTEGRATIONS-16 — App Store Connect: verification is a real `GET /v1/apps` call with an ES256 JWT that lives 15 minutes. If verification fails, the key is destroyed (not kept), the installation is `error` with a sanitized category, and the customer re-pastes the key to retry. Up to 10 validation attempts per org per hour. — "Do not declare success from JWT signing alone." — §5.
- INTEGRATIONS-17 — Google Play: saving the package and bucket stores public config only, with status `verifying` (shown as "Awaiting verification"). It never becomes `connected` until a verification run, which needs this product's Google Cloud credentials (not provisioned), succeeds. — "A bucket name … alone is not approval." — §5.
- INTEGRATIONS-18 — The AI assistant (MCP) card shows the "not deployed" state with no URL or connection code, because `capability("mcp")` is not configured. — Honest states. — production-ui-plan "AI/MCP".
- INTEGRATIONS-19 — Members can see each integration's status, the Organization ID and the API base URL. Token metadata (labels, prefixes, last use) is shown to owners only. — The token list is administrative data. — §2 policy table.
- INTEGRATIONS-20 — The API reference is an in-app page (`/home/<org>/integrations/api`), and the full text is in `docs/api.md`. The reference product's docs are never linked. — The reference product's docs belong to another product. — CLAUDE.md non-negotiable 1.
