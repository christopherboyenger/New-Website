# Ads area decisions

Format: `ADS-NN — decision — rationale — spec reference`. Nothing here is claimed as observed reference behavior beyond what the cited live states show.

- ADS-01 — An ad account counts as connected only when its `integration_installations` row has status `connected`. Other existing installations (for example `reauthorization_required` or `error`) are named with what's wrong, next to the "Go to Integrations" prerequisite. — "Connected" is set only after provider verification. A degraded grant must not look launchable. — production-integration-contracts.md §3; build spec L08/L38.
- ADS-02 — Paid-use rights for organic posts live in a new `ad_rights_grants` table (`src/server/db/schema/ext-ads.ts`). A grant records the creator, the post, the providers it covers, the evidence kind and reference, and when it was granted, expires and was revoked. A post can be drafted as an ad only if it is approved and has an unrevoked, unexpired grant covering the chosen provider. Direct submissions must be `accepted`, have `rights_granted_at` set, have an expiry that is unset or in the future, and have a media asset. The rights evidence is copied into `ad_launches.rights_evidence` when the draft is saved. — Organic ownership or approval does not grant paid-ad rights. Expiry and revocation must block launches. — production-requirements.md "Ads and rights"; build spec acceptance item 13.
- ADS-03 — Native placement rule: TikTok ads run TikTok posts only, and Meta ads run Instagram and Facebook posts only. A post also needs its provider content ID (`posts.external_id`) before it is eligible. — Spark/partnership-style ads reference the creator's existing platform post. Uploaded media is not available yet because media storage isn't configured. — production-requirements.md "Ads and rights"; readiness `media_storage`.
- ADS-04 — "Save draft" creates exactly one `ad_launches` row in stage `draft`, with an audit entry. It makes no provider call and sets no external IDs. Launch is a disabled button with the reason shown, because this deployment has no launch adapter. At most one non-failed or non-rejected launch can exist per source and provider; a second draft attempt is rejected as a conflict. — Edits never publish, activate or charge. The saga's later stages need a provider adapter. — CLAUDE.md non-negotiable 5; production-integration-contracts.md §6; production-ui-plan.md ads/new row.
- ADS-05 — A draft carries the `ad_settings.version` that the form was built from. If the settings changed since then, saving fails with a conflict ("reload to use the current defaults"). The ad name is generated on the server from the current convention, and the destination URL is resolved on the server from the current link settings for that provider. Neither is taken from the client, except an optional name override. — The saga begins with "verify grant/rights/settings/version". — production-integration-contracts.md §6.
- ADS-06 — CTA catalogs are a subset of the providers' public CTA enums: Meta `call_to_action.type` and TikTok `call_to_action`, listed in `src/components/ads/cta-catalog.ts`. They must be checked again against the API versions a launch adapter pins before launching is enabled. — The reference CTA choices were never opened (L28). — build spec "Ads and advertising defaults".
- ADS-07 — Naming convention: ordered fields (Custom text, Date, Creator), with Date and Creator allowed at most once each, up to 6 fields, and a separator from `_ - | .`. Date is the launch-draft day in UTC, formatted `YYYYMMDD`. Creator is the post handle, or the creator's display name for a submission. Field values are sanitized: whitespace becomes `-`, only letters, digits and `- _ . @` are kept, the active separator is removed, and each field is capped at 40 characters. Every generated name ends with the product's post or submission ID; this tail is not configurable and is kept even when the head is truncated to fit 250 characters. An individual ad can override the whole name; the source ID is still stored on the launch row. Fields are reordered with Move up / Move down buttons, with a screen-reader announcement; there is no drag. — L26 shows Custom/Date/Creator, a separator, the "always ends in ID" rule, and that individual ads can override. The reference date format was not observed. — build spec "Ads and advertising defaults".
- ADS-08 — URL parameters: the website URL must be an absolute `https://` URL with a real host and no credentials. Keys match `[A-Za-z0-9_.-[]]{1,64}`, must be unique ignoring case, and there can be at most 20. Values may only contain `{{platform}}` and these Meta macros: `ad.id ad.name adset.id adset.name campaign.id campaign.name placement site_source_name`. Values are percent-encoded, but macros are left literal. `{{platform}}` resolves to `meta` or `tiktok`. A parameter that uses a Meta macro is left out of the TikTok URL, and the preview says so. A settings key that already appears in the website URL's query replaces it. — L27 documents `{{platform}}` and Meta macros. How TikTok handles Meta macros is not specified, and sending a literal `{{adset.id}}` to TikTok would be wrong. — build spec "Ads and advertising defaults".
- ADS-09 — Copy-template tokens are `{{creator}}`, `{{handle}}`, `{{brand}}` and `{{hashtag}}` (the campaign's primary hashtag). Unknown tokens are rejected on save. A token with no value for a given post is removed, and the draft form warns about it. Body copy saved in a draft cannot contain unresolved tokens. The settings preview uses example values that are labelled as examples. There can be at most 10 templates of up to 2,000 characters each. — L11 says tokens are replaced per post but does not show a catalog. — build spec "Ads and advertising defaults".
- ADS-10 — A workspace without an `ad_settings` row (version 0) shows the product defaults: Date + Creator, separator `_`, no templates, no URL, no CTA. Its first save inserts the row at version 1; a race on that insert is reported as a conflict. — Organizations created before or outside the foundation's insert must still work. — CLAUDE.md optimistic concurrency.
- ADS-11 — The Ads date range filters ad launches and submissions by creation time, using UTC days inclusive. Lists are paginated on the server, 25 per page. `view=submissions` is the only other view; anything else shows All ads. — L08/L37 show a date range but not which field it filters. — build spec acceptance item 8.
- ADS-12 — No ad performance numbers are shown anywhere. A "not available" notice says that impressions, spend and results aren't imported on this deployment. — There is no reporting adapter, and numbers must never be fabricated. — CLAUDE.md non-negotiable 2.
- ADS-13 — Members can view Ads, Submissions and Ad settings in read-only mode. Create ads is disabled for them with the reason shown, and `/ads/new` explains that an Owner is needed. Server commands require `ads:launch` or `ad_settings:edit`, which only Owners have. — DEC-005. — docs/decisions.md.
