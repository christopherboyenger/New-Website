# End-to-end test decisions

Format: `E2E-NN — decision — rationale — spec reference`.

- E2E-01 — The Playwright suite runs against `next dev` with a throwaway embedded database (`.data/pglite-e2e`, deleted before each run) and no provider credentials. Journeys assert the honest states of such a deployment (email "not delivered" with links read from `/dev/outbox`, "card payments aren't configured", reach estimate unavailable) instead of faking provider success. — A test that fakes a provider success would contradict non-negotiable 2. — CLAUDE.md "Honest states"; docs/readiness.md.
- E2E-02 — The single exception is a test-only route, `POST /api/e2e/payment-method`, that records the signed-in owner's payment method as provider-confirmed so the creator journey can publish and activate through the real UI. The file is named `route.e2e.ts` and is a route only when `E2E_TEST_HOOKS=1` and `NODE_ENV` is not production (`pageExtensions` in `next.config.ts`); in every other build it is not compiled. The handler (in `tests/e2e/support/`) also refuses production, `DATABASE_URL` and anyone who is not an owner of the workspace. — PGlite allows one process at a time, so a script cannot write to the database while the dev server holds it, and no Stripe test account is available to the suite. Keeping the hook outside the normal page extensions makes it impossible to ship by accident. — task brief (journey 4); commercial-policy `publishing.requiresPaymentMethod`.
- E2E-03 — The reporting-API journey moves only the browser clock forward 31 minutes to reach the password step-up, because a new session already counts as recently authenticated. The server still checks recent authentication with its own clock. — Exercises the step-up dialog without waiting 30 minutes. — DEC-003 (recent-auth step-up).
