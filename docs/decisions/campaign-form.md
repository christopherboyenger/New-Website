# New campaign form — decisions

Format: `CAMPAIGN-FORM-NN — decision — rationale — spec reference`. Everything here is **proposed** behavior for this product; none of it is claimed as recovered reference behavior.

- **CAMPAIGN-FORM-01** — Creating a campaign is the only write on `/home/{org}/campaigns/new`. It always creates the campaign Inactive (foundation `createCampaign`), never activates, publishes or charges, and on success navigates to `/home/{org}/campaigns?tab=campaigns&created=<id>` with a toast saying the campaign stays Inactive until activated. Enter in a text field does not submit; only the Create campaign button does. — Edits/creation must never activate or charge; the reference action was not submitted. — CLAUDE.md non-negotiable 5; reference-build-specification.md "Campaign creation" (L17–L22); "Documented campaign behavior" (campaigns begin inactive).
- **CAMPAIGN-FORM-02** — Manual pricing stays visible (with "Requires Unlimited" on plans without `manual_pricing`) but is disabled on every plan with "Not available yet" and an explanation; the server rejects `pricingMode: "manual"` on every plan. — No manual rate-card model exists and the Manual sub-form was never observed; accepting Manual would persist a campaign with no rates. — L18; "Current UI versus documentation" (Daily/Manual ↔ dynamic/fixed unverified); DEC-006.
- **CAMPAIGN-FORM-03** — The Estimates panel shows exactly what `forecastReach()` returns. Today that is "Reach estimate unavailable" with the service's reason; no numbers, meters or placeholder ranges. Changing budget/format/targeting re-requests the estimate (600 ms debounce) and shows "Updating…" instead of the previous result. The panel separately restates the user's own budget input (daily and 7× weekly average). — Reference figures were transient and not a formula. — DEC-008; production-ui-plan.md "/home/{org}/campaigns/new" (estimates unavailable without a real model).
- **CAMPAIGN-FORM-04** — Budget copy is adapted to this product's lifecycle: "Your budget applies once you activate this campaign. Spend may run higher at first to attract creators, averaging out to $X/week." The reference's "Your budget starts on the day you create this campaign" and the claim that "CPMs adjust day to day…" are not used, because creation is Inactive and no pricing controller exists. "Daily spend is an average, not a cap" and the 7× weekly average are kept. — Honest copy. — L18; DEC-015; "Documented campaign behavior" (averaging over a week).
- **CAMPAIGN-FORM-05** — Budget input: dollars typed into a number field and a slider ($50–$5,000, $10 steps); larger amounts can be typed (server max $1,000,000/day). Parsing to integer cents is exact (no floats); the $50 minimum is enforced by the server schema and shown as a field error. — Slider range was not observed. — L18; DEC-015.
- **CAMPAIGN-FORM-06** — Country filter uses all 249 ISO 3166-1 alpha-2 codes with names from `Intl.DisplayNames` (stored as codes); the server rejects codes not in the catalog. US metro "Locations" use the 50 most populous Census MSAs with stable slug IDs (`src/domain/targeting-catalog.ts`). — The reference option catalogs were never opened. — "Campaign creation" ("catalogs were not exhaustively opened").
- **CAMPAIGN-FORM-07** — Metro targeting only applies when US creators are in scope (no country filter, or a filter including US). The Locations filter is disabled with an explanation otherwise, and the server rejects metros without US in scope ("Add United States to Countries, or remove the metro filter"). — The reference description says "US creators in these metro areas"; combining metros with non-US countries is contradictory. — L19.
- **CAMPAIGN-FORM-08** — Age range is two optional whole-number bounds (13–100, min ≤ max); gender is All genders / Female / Male (single choice). — Age/gender option catalogs were not opened; values follow the shared domain vocabulary. — L19; `src/domain/campaign.ts`.
- **CAMPAIGN-FORM-09** — Recommended hashtags are try<Org>, join<Org>, <Org>App, derived from the workspace name (ASCII letters/digits, words capitalized), and only those not used by any campaign on the platform are shown. The hashtag field checks availability live (400 ms debounce, 60 checks/user/minute) and the server re-checks on create (HashtagTakenError → field error). A taken hashtag message never reveals which workspace uses it. — Observed recommendation pattern; uniqueness is platform-wide. — L17; DEC-010.
- **CAMPAIGN-FORM-10** — Plan gates: on plans without the feature the control is disabled, carries "Requires Unlimited", and a note explains it; owners (billing:view) get an "Upgrade to Unlimited" link to `/home/{org}/billing`. The server still rejects gated settings (`EntitlementError`/`missingEntitlements`) and maps each to its field, then the form jumps to the first invalid section. The Approvals nav entry shows the badge only when its settings are gated. — UI badges are cosmetic; commands enforce. — DEC-006; L17–L22.
- **CAMPAIGN-FORM-11** — Members (no `campaign:manage`) get a read-only explanation instead of the form, with a link back to Campaigns. Every Server Action re-checks `campaign:manage`; other workspaces and nonexistent slugs both return not found. — Authorization on the server. — CLAUDE.md non-negotiable 3; production-requirements roles.
- **CAMPAIGN-FORM-12** — Unsaved changes: leaving through the in-page links (Campaigns back link, upgrade links) opens a "Leave without creating?" dialog; reloads/tab closes use the browser's beforeunload prompt. Browser back/forward within the app is not intercepted. — The reference behavior was not observed. — production-ui-plan.md (unsaved-change protection).
- **CAMPAIGN-FORM-13** — Mobile (<768px): the section navigation becomes a labelled native select showing each section's summary; the active section is followed by Previous/Next buttons and the Estimates panel; Create campaign is a sticky bottom bar. Touch targets are ≥44px. — Mobile layout was not inspected. — production-ui-plan.md "Proposed mobile and accessibility behavior".
- **CAMPAIGN-FORM-14** — Content illustrations are neutral geometric SVGs (no people, faces, captions or real creator posts) until approved assets exist. — The reference shows real creator media that cannot be reused. — production-ui-plan.md "Asset requirements"; B04.
