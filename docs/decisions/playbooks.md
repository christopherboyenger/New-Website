# Playbooks area decisions

Format: `PLAYBOOKS-NN — decision — rationale — spec reference`.

- PLAYBOOKS-01 — Drafts save explicitly (Save button, Cmd/Ctrl+S, and Save in Hashtags & Descriptions). There is no autosave. The header shows Saved / Saving… / Unsaved changes / Conflict / Not saved, and leaving with unsaved changes asks first (in-app back link plus the browser unload prompt). — Autosave was never observed. Explicit saves keep optimistic-concurrency conflicts understandable. — reference-build-specification.md "Playbook creation and UGC editor" ("autosave/persistence … not tested"); evidence audit item 9.
- PLAYBOOKS-02 — Concurrency uses `playbooks.version`. A save carries the version the client loaded. A mismatch writes nothing and returns a conflict with a "Reload latest" action, which replaces the tab's unsaved edits with the latest saved draft. Publish also requires the version the owner is looking at. — Multi-tab edits must not silently overwrite each other. — Acceptance criterion 12; production-ui-plan.md editor row ("revision conflicts").
- PLAYBOOKS-03 — Publish rules: the playbook has a campaign and a name. UGC needs at least one scene, every scene needs instructions, and there can be no blank on-screen text options. Slideshow needs at least one slide, every slide needs at least one caption, and there can be no blank captions. There must be at least one non-blank description, with no blank description options next to filled ones. Drafts may be incomplete. — The reference publish checks are unknown. These are the minimum a creator needs to follow the brief. — Implementation handoff "Playbook: … Publication checks … Noise's exact checks are unknown".
- PLAYBOOKS-04 — Publishing is owner-only (`playbook:publish`). When `commercialPolicy.publishing.requiresPaymentMethod` is true, it also needs a provider-confirmed ready payment method. When card payments aren't configured on the deployment, the dialog says so instead of linking to a Billing flow that can't work. — DEC-005 matrix; commercial policy. — production-requirements.md "Campaign and playbook operations".
- PLAYBOOKS-05 — Every publish freezes a new `playbook_revisions` row (revision = previous max + 1) with a copy of the name, content, descriptions and hashtags. The draft keeps evolving. "Unpublished changes" means the saved draft differs from the published revision; key order is ignored when comparing. — Later edits must not rewrite what creators were given. — production-requirements.md "Freeze the playbook/version".
- PLAYBOOKS-06 — The publish dialog's "Make available to creators while the campaign is active" checkbox sets `active` to exactly the ticked value. It starts unticked for a first publish and reflects the current state on a republish. Publishing never changes campaign status and never charges. — Distribution is an explicit choice, kept separate from campaign activation. — Evidence audit item 5; non-negotiable 5.
- PLAYBOOKS-07 — Media storage isn't provisioned, so references and slideshow image options are external `https` links with an optional title. `assetId` must be null, and links are validated but never fetched or embedded. The preview shows neutral placeholders with the link host. — Honest "not configured" state; no third-party media loaded into the dashboard. — readiness `media_storage`; production-ui-plan.md editor row.
- PLAYBOOKS-08 — Unique-script math: UGC = Π max(1, non-blank on-screen text options per scene) × max(1, non-blank descriptions). Slideshow = Π max(1, image options) × max(1, non-blank captions) per slide × max(1, descriptions). Hashtags never multiply. Blank options don't count. — Reproduces L06 (two scenes, two descriptions = 2). Slideshow follows the documented one-image/one-caption-per-slide rule. — L06; "Playbook guide scope".
- PLAYBOOKS-09 — Hashtags are normalized with `normalizeHashtag`, validated with `isValidHashtag`, deduplicated, limited to 30, and may never equal the campaign primary hashtag, which is always appended last. UGC posts carry every playbook hashtag. Slideshow posts sample 2–3 (all of them when fewer than 3), shown in the preview only. — The documented formats differ and are kept apart. — Evidence audit item 7; DEC-010.
- PLAYBOOKS-10 — Applying a template (only the playbook's own format, DEC-009) replaces content and descriptions after a confirmation when the draft has content. Hashtags are kept, and scenes and slides get fresh IDs. It changes only the local draft until saved. — Templates ship without hashtags, so keeping the brand's hashtags avoids accidental loss. — DEC-009; evidence audit item 6.
- PLAYBOOKS-11 — The Agent pane states that AI authoring isn't available on this deployment (`capability("ai_authoring")`) and offers templates. No AI calls are made. — Honest not-configured state. — Non-negotiable 2.
- PLAYBOOKS-12 — Draft limits: name 120, instructions 5,000, scene name 120, on-screen text and captions 300, descriptions 2,200, 30 scenes, 20 slides, 20 options per item, 20 references, 30 hashtags. A blank name saves as "Untitled playbook". — These limits were never observed. They keep payloads bounded, and 2,200 matches the longest common platform caption. — Reference-screen-inventory unknowns (form limits).
- PLAYBOOKS-13 — Members can open and save drafts. They don't see Publish, and a notice explains that only owners publish. Payment readiness isn't sent to members. — DEC-005 (playbook:edit vs playbook:publish); billing is owner-only. — Documented roles.
